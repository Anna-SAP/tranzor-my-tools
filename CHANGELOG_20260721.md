Updated **TranzorExporter.exe** (v20260721)

What's new in 21 July update:

- 🏷️ **Title column (MR Pipeline)** — a flexible **Title** column now sits next to **JIRA** and uses the same cached GitLab MR metadata, so every ID/title pair stays mapped to the same project + MR. The column alone absorbs available window width; titles stay on one line and are pixel-fitted with `...` when space runs out. Hovering a genuinely truncated Title opens a dark Tooltip with the complete text, while untruncated cells remain quiet. If a future task payload supplies `jira_title`, `jira_ticket_title`, or `jira_summary`, that authoritative value is preferred automatically.
- 🎫 **JIRA column (MR Pipeline)** — the task table gains a **JIRA** column right after MR#. In JIRA-driven agile work one ticket usually spans several MRs (`BUP-4360` → MR1…MR4), and those MRs' translation tasks are *same-origin*; the new column extracts the ticket ID (`KEY-123` pattern) from each MR's GitLab title so sibling tasks group at a glance. Cells fill in asynchronously ("…" → `BUP-4360` / "—") — one title fetch per distinct MR serves every row of that MR, results are cached for the session, and the ID is regex-guarded against release-number lookalikes (`BUI-26.3.1` never yields a fake `BUI-26`) and ticket-shaped acronyms (`UTF-8` / `SHA-256` / `CVE-2024-…` are never mistaken for tickets). Chinese titles work too — `修复BUP-4360购买流程` extracts `BUP-4360` even with the ID flush against CJK text. Needs a configured GitLab token; without one the column shows "—" up front instead of a spinner that never resolves. Sorting by the column works like any other (click the header), with unresolved cells sinking to the bottom.
- 🔎 **JIRA ID filter (MR Pipeline)** — paste an exact ticket ID such as `BUP-4360` into the new top-bar field (lowercase is normalized automatically) and press Enter or Search to find all translation tasks triggered by that ticket's MRs. The lookup uses GitLab's title search first, then intersects the matching project/MR pairs with the existing Project, Release, Status, MR#, Task ID and Hide-empty filters; Reset clears it with the rest. Cross-project searches are supported, while exact extraction keeps a title's secondary/related ticket from being mistaken for the row's displayed JIRA.
- 🔍 **Searchable Project dropdown (MR Pipeline)** — the Project filter no longer opens the native scroll-only list. Clicking it (or pressing ↓ / space) now pops a dark-themed panel with a **search box pinned at the top**: type any keyword (`fiji`, `corelib`, `voice`, …) and the project list below live-filters with case-insensitive substring matching — no more scrolling through a hundred long repo paths like `CoreLib/RoomsController` to find one entry.
- ⌨️ **Full keyboard flow** — the search box is auto-focused on open; ↑/↓ move the highlight while you keep typing, Enter picks the highlighted project, Esc (or clicking anywhere outside) closes. Reopening pre-selects the current choice; the blank "no filter" entry shows as a proper *(All)* row instead of an empty line, and an explicit *(no match)* hint appears when nothing fits.
- 🧩 **Drop-in component** — shipped as a reusable `searchable_combobox` module (same zero-dependency dark-popup pattern as the 📅 date picker): options are re-read from the combobox on every open so the async filter load needs no extra wiring, and the standard `<<ComboboxSelected>>` event still fires for downstream code. Localized en/zh, registered in both Windows and macOS PyInstaller specs.
