Updated **TranzorExporter.exe** (v20260805)

What's new in 5 August update:

- 🟢 **Platform status pill (Full Translations)** — a live connection indicator now sits at the top-right of the Full Translation tab, answering "is now a good time for a heavy full export?" before you click. Every 30s a lightweight probe (`GET /api/v1/legacy/tasks?limit=1` — the exact auth + DB path `fetch_tasks()` uses, falling back to unauthenticated `/livez` when signed out) is timed client-side: **green** ≤1s, **amber** 1–10s, **red** on timeout / connection failure / 5xx / 429, **gray** when unknown, stale (>90s without a sample — the pill never freezes on an outdated green) or re-login is needed (401 probes auto-downgrade to `/livez` until a fresh token appears, so an expired token doesn't spam the platform log). Recovery is deliberately skeptical: one good sample never clears a red — two consecutive greens are required, and a green light within 10 minutes of trouble renders as **"平台正常\*"** with the incident in the hover tooltip (the 2026-08-05 outage was bursty: fine at 11:00, dead 09:43–10:19). The probe runs on its own `requests.Session` and **never touches the `_HTTP_GATE`**, so it keeps telling the truth even when the exporter's own connections are wedged. Click the pill to probe immediately.
- 🚦 **Soft export gate** — Export Selected / Export All / Merge to JSON now pass a connection check right after the sign-in preflight: green proceeds silently (zero friction on healthy days), amber/unknown ask one soft question, red asks with **No** as the default. Buttons are never disabled — a stale or wrong red light must not lock you out. If the state flips to red while the confirm dialog sits open, a fresh check catches it after you answer.
- 📡 **In-export telemetry (channel B)** — while an export runs, the active probe pauses and the pill switches to passive telemetry from the real traffic: `_api_get` now registers every request in an in-flight table, observes `_HTTP_GATE` waits, and records retry/`Retry-After` events. The morning-of-8/5 failure signature — frozen sockets holding both gate permits while the GUI shows nothing — now surfaces as **"● 已 N 分钟无响应"** within ~2 minutes (HTTP silence AND progress-heartbeat silence both >120s), and a stuck request shows up as **"● 有请求已卡 Ns"** even while other responses still flow. Because the progress dialog is modal (`grab_set` makes the header pill unhoverable mid-export), the same status line lives **inside the export dialog**, with an escalating ⚠ alarm line appended to the activity log every 60s while a wedge persists.
- 💓 **Progress heartbeat + worker liveness** — every progress-log callback doubles as a heartbeat, so MR/Scan phases (which carry no legacy HTTP telemetry) are still covered; pure MR/Scan exports say so honestly ("仅进度心跳" wording, relaxed thresholds — a 2-minute git-clone silence is not an incident). If the export worker thread dies without reporting back, the dialog flips to an error view, the tab unlocks, and the pill says **"导出线程已终止"** instead of pretending all is well.
- 😴 **Suspend-proof** — wall-vs-monotonic clock-skew detection resets all silence baselines after laptop sleep/resume, so reopening the lid mid-export doesn't fire a false "no response for 10 min" alarm.
- 📝 **Forensic log** — state transitions and every retry (with observed `Retry-After` values) append to `~/.tranzor_exporter/conn_health.log` (1MB rotation; disable with `TRANZOR_HEALTH_LOG=0`). The packaged exe is `console=False`, which used to swallow every retry `print()` — the 8/5 retry storm left zero trace; now it can't.
- 🧪 **84 new tests** — pure-function thresholds/hysteresis/staleness, monitor behavior with an injected fake transport, `_api_get` telemetry embeds (zero behavior change when `conn_health` is absent or broken — CLI usage untouched), and Tk-free GUI surgery tests for the pill, tick loop, soft gate and dialog alarms. All thresholds are module constants overridable via `TRANZOR_HEALTH_*` env vars (they rest on one day of measurements so far).

Design doc: `Connection_Health_Indicator_PRD.md` (PR1 scope). Root-cause hardening (Retry-After cap, gate-acquire timeout, `fetch_tasks` per-page progress) lands separately as PR2.
